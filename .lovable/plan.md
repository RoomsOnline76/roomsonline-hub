

## Fix Push_PutProperty_RQ XML to Match RU Documentation

### Problem
The XML generated by `rentalsunited-api/index.ts` for `Push_PutProperty_RQ` has the wrong element order, wrong values, missing mandatory fields, and structural issues compared to the [official RU documentation](https://developer.rentalsunited.com/?xml#put-property). This causes Error 2xx (validation failures) on every push attempt.

### Issues Found (comparing our XML vs RU docs)

| Issue | Our Code | RU Expects |
|-------|----------|------------|
| **IsActive/IsArchived values** | `1` / `0` | `true` / `false` |
| **Element order** | ID, IsActive, Name, ObjectTypeID... | Name, OwnerID, DetailedLocationID, IsActive, IsArchived, Space, StandardGuests, CanSleepMax, PropertyTypeID... |
| **Missing: OwnerID** | Not sent | Mandatory (M) |
| **Missing: PropertyTypeID** | Uses `<ObjectTypeID>` tag | Must be `<PropertyTypeID>` |
| **Missing: NoOfUnits** | Not sent | Optional but expected |
| **CheckIn/Out structure** | Flat: `<CheckInFrom>`, `<CheckInTo>`, `<CheckOutUntil>` | Wrapped: `<CheckInOut><CheckInFrom>10:00</CheckInFrom><CheckInTo>13:00</CheckInTo><CheckOutUntil>09:00</CheckOutUntil><Place>apartment</Place></CheckInOut>` |
| **SecurityDeposit** | `<SecurityDeposit>X</SecurityDeposit>` | `<SecurityDeposit DepositTypeID="5">X</SecurityDeposit>` (attribute required) |
| **CompositionRoomsAmenities** | Included in XML | Should only be sent when detailed room amenities exist |
| **Descriptions placement** | Before Images | Should come after CancellationPolicies |

### Correct Element Order (from RU docs Example 1)

```text
<Property>
  <PUID BuildingID="-1">...</PUID>        (optional)
  <Name>...</Name>                          (M)
  <OwnerID>...</OwnerID>                    (M)
  <DetailedLocationID TypeID="4">...</DetailedLocationID>  (M)
  <IsActive>true</IsActive>                (M)
  <IsArchived>false</IsArchived>            (M)
  <Space>...</Space>                        (O)
  <StandardGuests>...</StandardGuests>      (M)
  <CanSleepMax>...</CanSleepMax>            (M)
  <PropertyTypeID>...</PropertyTypeID>      (M)
  <NoOfUnits>1</NoOfUnits>                 (O)
  <Floor>...</Floor>                        (O)
  <NumberOfFloors>...</NumberOfFloors>      (O)
  <Street>...</Street>                      (M)
  <ZipCode>...</ZipCode>                    (M)
  <Coordinates>...</Coordinates>            (C)
  <Distances>...</Distances>                (O)
  <Amenities>...</Amenities>                (C,O)
  <Images>...</Images>                      
  <ArrivalInstructions>...</ArrivalInstructions> (O)
  <CheckInOut>...</CheckInOut>              
  <PaymentMethods>...</PaymentMethods>      
  <Deposit DepositTypeID="5">...</Deposit>  (O)
  <CancellationPolicies>...</CancellationPolicies>
  <Descriptions>...</Descriptions>          
  <SecurityDeposit DepositTypeID="5">...</SecurityDeposit> (O)
  <CompositionRoomsAmenities>...</CompositionRoomsAmenities> (C,O)
  <LicenceInfo>...</LicenceInfo>            (O)
</Property>
```

### Changes

**File: `supabase/functions/rentalsunited-api/index.ts`**

1. **Rewrite `buildPushPropertyXml`** to match the exact RU element order above
2. Change `<IsActive>1</IsActive>` → `<IsActive>true</IsActive>` and `<IsArchived>0</IsArchived>` → `<IsArchived>false</IsArchived>`
3. Add mandatory `<OwnerID>` element (default to `1` if not provided)
4. Rename `<ObjectTypeID>` → `<PropertyTypeID>`
5. Add `<NoOfUnits>1</NoOfUnits>`
6. Wrap check-in/out in `<CheckInOut>` container with `<Place>apartment</Place>`
7. Move `<Descriptions>` after `<CancellationPolicies>`
8. Remove `<CompositionRoomsAmenities>` from default push (only needed for detailed room amenities)
9. Add `DepositTypeID="5"` attribute to `<SecurityDeposit>`
10. Add `TypeID="4"` attribute to `<DetailedLocationID>`
11. Remove `<?xml version="1.0" encoding="utf-8"?>` declaration (RU docs say requests must be compacted without XML declaration)

**File: `supabase/functions/rentalsunited-api/index.ts`** (interface)
- Add `standard_guests`, `owner_id`, `no_of_units`, `property_type_id` to `RUPropertyPayload`

**File: `supabase/functions/push-property-to-ru/index.ts`**
- Add `owner_id: 1` and `no_of_units: 1` to the payload built by `buildRUPayload`
- Rename `object_type_id` → `property_type_id` in the payload

### Technical Detail
The XML must follow the XSD schema strictly — elements out of order cause "invalid child element" errors even if the values are correct.
